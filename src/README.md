# Apps Script への設置

`Code.gs` と `appsscript.json` を、Google スプレッドシートに紐づいた Apps Script プロジェクトに入れて使います。

## デモを動かす

1. Google スプレッドシートを新しく作り、拡張機能 > Apps Script を開きます。
2. 既定のコードを `Code.gs` の中身で置き換えます。`appsscript.json` も同じ内容にします（エディタの設定で「マニフェストを表示」をオンにすると編集できます）。
3. `CONFIG.DEMO_MODE` が `true` のまま、関数 `generateInvoices` を実行します。初回は権限の許可を求められます。
4. 起きること:
   - 「取引先マスタ」「明細」シートに架空のサンプルデータが入ります。
   - 対象月 2026-07 の請求書PDFが3件、Drive の「請求書出力(デモ)」フォルダにできます。C001 は月まとめで1件、C002 は請求単位「案件A」「案件B」ごとに1件ずつです。
   - 「発行台帳」に請求書番号・金額・PDFのリンクが記録されます。
5. もう一度実行しても、発行台帳にある分（取引先・対象月・請求単位が同じもの）は発行しません。

2回目からは、メニュー「請求書」>「請求書を生成」か、「明細」シート右上のボタンからも実行できます。

## 実データに切り替える

1. `CONFIG.DEMO_MODE` を `false` にします。
2. `CONFIG.ISSUER` を発行者の情報にします。登録番号は適格請求書発行事業者の T と13桁の数字です。
3. シートに実データを入れます。列の見出しは次のとおりです。
   - 取引先マスタ: 取引先コード / 取引先名 / 住所 / 登録番号 / 振込先 / 支払期限
   - 明細: 対象月(YYYY-MM) / 取引先コード / 請求単位 / 日付 / 品目 / 数量 / 単価(税抜) / 税率(0.10 か 0.08)
4. `CONFIG.TARGET_MONTH`、`CONFIG.ROUNDING`（floor / round / ceil）、`CONFIG.PAYMENT_DUE` を決めます。

支払期限の列には「翌月末」か「発行日+30」のように書きます。空欄や読めない値のときは `CONFIG.PAYMENT_DUE` を使い、読めない値のときは Apps Script の実行ログ（`Logger`）に警告を残します。

請求単位が空欄の行は、取引先ごとに月まとめの請求書になります。請求単位を書くと、その単位ごとに別の請求書になり、明細に日付の列が出ます。

## 決まった日の自動発行

1. メニュー「請求書」>「自動発行を有効にする」を実行します。「自動発行設定」シートが初期値つきで作られ、毎日1回動くトリガーができます。
2. 設定は「自動発行設定」シートの設定値の列だけで変えます。

| 項目 | 例 | 意味 |
|---|---|---|
| 自動発行 | ON | OFF にすると発行しません |
| 発行日 | 25 / 月末 | 毎月この日に発行します。31日が無い月は末日にずらします |
| 対象月 | 前月 / 当月 | 前月なら 8月25日に 7月分を発行します |
| 実行時刻 | 9 | 0〜23。変えたらトリガーを作り直します |

トリガーは作った人のアカウントで動きます。そのため、この操作は実際に使う人が自分で行う必要があります。
止めるときはメニュー「請求書」>「自動発行を止める」を実行します。

自動発行が失敗したときだけ、トリガーを作った本人のアドレスにメールが1通届きます。宛先は `Session.getEffectiveUser()` で決まり、設定で変えることはできません。

## 追加機能のスイッチ

`CONFIG.OPTIONS` の3つの値で、追加機能を個別に止められます。

- `SCHEDULED_ISSUE`: 決まった日の自動発行
- `RUN_LOG`: 「実行ログ」シートへの記録
- `ERROR_MAIL`: 自動発行が失敗したときのメール
